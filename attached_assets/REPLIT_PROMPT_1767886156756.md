# Context Foundry Aggregation Framework Integration

## Task
Integrate the Aggregation Framework into Context Foundry to handle quantitative queries ("How many X?", "What's the average Y?") without hallucinating numbers.

## Files Provided
- `cf_aggregation_framework_scaffold.zip` - Complete Python implementation scaffold
- `CF_Aggregation_Framework_v1.3_Final.docx` - Full specification (reference)

## What To Do

### 1. Unzip and copy the aggregation module
```bash
unzip cf_aggregation_framework_scaffold.zip
cp -r cf_aggregation_scaffold/aggregation/ src/context_foundry/aggregation/
```

### 2. Run the database migration
Copy `cf_aggregation_scaffold/migrations/001_aggregation_framework.py` to your migrations folder and run:
```bash
alembic upgrade head
```

This creates 3 tables with RLS:
- `agg_definitions` - Semantic contracts
- `aggregation_metadata` - Result cache  
- `doc_entity_mentions` - Document mention index

### 3. Hook into ContextFoundry.query()
In `src/context_foundry/agents/retrieval.py`, add this BEFORE the tri-memory pipeline:

```python
from context_foundry.aggregation import try_aggregation_query

# Inside query() method, after intent classification:
if self.feature_flags.get("aggregation.enabled", False):
    agg_result = try_aggregation_query(
        session=self.session,
        tenant_id=self.tenant_id,
        question=question,
        user_ctx=user_ctx,
        anchor_entities=resolved_entities,
        feature_flags=self.feature_flags,
    )
    if agg_result is not None:
        return self._format_aggregation_response(agg_result)
# Continue with normal pipeline if not aggregation...
```

## Critical Rules (DO NOT VIOLATE)

1. **NO COUNTING FROM RETRIEVAL** - Never use top-K retrieval results as complete sets
2. **RLS ALWAYS** - All queries must use the existing SQLAlchemy session (tenant isolation automatic)
3. **DETERMINISTIC ONLY** - SQL templates in planner.py are pre-approved; never generate SQL from LLM
4. **RESULT KINDS** - Must return one of: EXACT, LOWER_BOUND, RANGE, or INSUFFICIENT

## Test It Works

```python
from context_foundry.aggregation import AggregationService

service = AggregationService(session, tenant_id)
result = service.handle_query("How many jobs has Saleh had?")

print(result.result_kind)    # EXACT, LOWER_BOUND, RANGE, or INSUFFICIENT
print(result.display_text)   # "4 jobs" or "At least 4 jobs"
print(result.confidence)     # 0.0-1.0
```

## Module Summary

| File | Purpose |
|------|---------|
| `service.py` | Main orchestrator - call `try_aggregation_query()` |
| `intent.py` | DSPy classifier (falls back to rules if DSPy not installed) |
| `registry.py` | CRUD for semantic contracts in `agg_definitions` |
| `planner.py` | Maps intent → SQL templates |
| `executor.py` | Runs SQL with RLS via existing session |
| `crc.py` | Lincoln-Petersen estimation for multi-source RANGE |
| `sufficiency.py` | Decides EXACT vs LOWER_BOUND vs RANGE vs INSUFFICIENT |
| `formatter.py` | Composes user-visible answers |
