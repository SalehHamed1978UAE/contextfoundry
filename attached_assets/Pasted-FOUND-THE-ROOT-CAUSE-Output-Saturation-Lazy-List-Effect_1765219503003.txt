FOUND THE ROOT CAUSE: "Output Saturation" (Lazy List Effect)

The LLM stops extracting after 10-15 entities because RLHF training 
penalizes long repetitive lists. It's not context limits — it's the 
model getting "bored."

SOLUTION: Chunk + Glean (Microsoft GraphRAG standard)

═══════════════════════════════════════════════════════════════
FIX 1: CHUNKING
═══════════════════════════════════════════════════════════════

Current: Processing 6,400-char document as single chunk
Problem: Model hits output saturation at ~12 entities

Change to:
- Chunk size: 2,000-2,500 characters (~600 tokens)
- Overlap: 100 tokens (~400 chars)
- Your test doc: Split into 3 chunks

Expected: Each chunk yields 7-10 entities → Total 20-30 entities

═══════════════════════════════════════════════════════════════
FIX 2: GLEANING PASS (The Secret Weapon)
═══════════════════════════════════════════════════════════════

After extraction, run a second pass per chunk:

GLEANING_PROMPT = """
You extracted these entities from the text:
{already_extracted}

Review the original text again and extract any entities you MISSED.
Return ONLY new entities not in the list above.

Text:
{chunk_text}
"""

This typically recovers 15-20% more entities.

═══════════════════════════════════════════════════════════════
FIX 3: ADD "EXHAUSTIVE" DIRECTIVE
═══════════════════════════════════════════════════════════════

Update prompt to override the conciseness bias:

"Extract ALL entities. Be EXHAUSTIVE. Do not stop until every 
single mention is captured. A short list is a FAILED extraction."
