FIX: ENTITY EXTRACTOR MISSING NEWLINE VALIDATION

Root cause: entity_extractor.py has its own _is_valid_entity_name() method 
that does NOT check for newlines. Corrupted entities slip through during 
LLM extraction parsing before entity_hygiene.py ever sees them.

================================================================================
THE FIX (Option A — Quick)
================================================================================

Add newline check to entity_extractor._is_valid_entity_name():

In `src/context_foundry/extraction/entity_extractor.py`, find `_is_valid_entity_name()` 
(around line 395) and add at the TOP of the function:
```python
def _is_valid_entity_name(self, name: str) -> bool:
    """Validate entity name from LLM extraction"""
    
    if not name:
        return False
    
    # CHECK FOR NEWLINES FIRST (before any other processing)
    if '\n' in name or '\r' in name:
        logger.warning(f"Rejecting entity with embedded newline: {repr(name[:50])}")
        return False
    
    # Check for double spaces (concatenation artifact)
    if '  ' in name:
        logger.warning(f"Rejecting entity with double space: {repr(name[:50])}")
        return False
    
    # ... rest of existing validation ...
```

================================================================================
THE FIX (Option B — Cleaner, DRY)
================================================================================

Have entity_extractor use the centralized validation:
```python
# At top of entity_extractor.py
from context_foundry.extraction.entity_hygiene import is_valid_entity_name

# Replace the _is_valid_entity_name method calls with:
if not is_valid_entity_name(entity_name):
    continue  # Skip invalid entity
```

This ensures ONE validation function is used everywhere.
