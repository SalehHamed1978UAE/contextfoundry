### 3. API Endpoints

**Check what endpoints actually exist.** The spec assumes:

| Endpoint | Purpose |
|----------|---------|
| `GET /api/vaults` | List vaults |
| `POST /api/vaults` | Create vault |
| `DELETE /api/vaults/{id}` | Delete vault |
| `POST /api/vaults/{id}/documents` | Upload document |
| `GET /api/vaults/{id}/documents` | List documents |
| `POST /api/vaults/{id}/query` | Query vault |
| `GET /api/vaults/{id}/extraction-status` | Get extraction progress |
| `GET /api/vaults/{id}/stats` | Get vault stats (chunk count) |

**If `/extraction-status` or `/stats` don't exist, you'll need to either:**
- Add them (simple endpoints that query the DB)
- Or use alternative methods (query extraction_requests table via an existing endpoint)

Let me know which endpoints exist and which are missing.

---

### 4. Auth Token

**Use the existing API key mechanism.** The test runner should:

1. Read token from `test_config.json` (already in the spec)
2. Or read from environment variable `CF_API_TOKEN`
3. Or prompt once and save to config

The token should be the same one used to access the UI — this ensures the vaults created are visible to the user.

```json
{
  "api_base_url": "http://localhost:5000/api",
  "auth_token": "${CF_API_TOKEN}",  // or actual token
  ...
}
```
