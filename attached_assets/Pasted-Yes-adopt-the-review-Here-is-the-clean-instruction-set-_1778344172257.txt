5. Design doc updates

Update:

docs/gap_detector_design_2026-05.md

Add cache and memoization invariants section

Use this corrected language:

Engine layer: FactEvaluator.evaluate(fact) has no memoization on fact.key(). Every invocation runs the full plan → presupposition → gather → adversary → prover → synth pipeline. The only instance-level cache is _authority_cache for source-authority sub-evaluations, scoped to a single FactEvaluator instance. Test runners that construct one FactEvaluator per question reset this cache between questions; long-lived servers that share an evaluator across requests would not.

RecursionGuard._path is cycle-detection only. Child guards copy the parent's path so sibling sub-evaluations of the same parent do not short-circuit each other.

LLM layer: LLM calls are cached in the llm_cache Postgres table, keyed by sha256(PROMPT_TEMPLATE_VERSION, SCHEMA_FIELD_VERSION, REASONING_ENGINE_VERSION, model, system_prompt, user_prompt, schema_name). Cache keys include prompt content, so changes to chunks included in the prompt invalidate downstream calls. Changes to retrieval logic that surface the same chunks do not invalidate.

A retrieval-logic change is not guaranteed to invalidate planner or presupposition-stage LLM calls, because those prompts may not include retrieved evidence. Clean measurement of retrieval changes therefore requires either a run-specific cache namespace/version or explicit cache bypass.

For clean measurement, use a run-specific cache namespace/version tag or perform a scoped deletion by tenant, run_id, or exact experiment window. Broad timestamp deletion should be a last resort.
