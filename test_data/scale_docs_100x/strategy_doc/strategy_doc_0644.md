# Microservices Refactoring Strategy

**Author:** Tatum Lewis
**Last Updated:** 2025-09-05
**Status:** In Review

## Executive Summary

This document outlines the strategic approach to microservices refactoring for the upcoming quarter. Key stakeholders include Backend Team and Security Team.

## Background

The need for microservices refactoring has become increasingly apparent as Email Service faces latency issues. Logan Jackson initially raised this concern in Q3.

## Proposed Approach

- Quinn Thompson raised concerns about resource exhaustion in the context of microservices refactoring.
- Quinn Thompson presented data showing improvements in Payment Service after implementing microservices refactoring.
- Quinn Thompson proposed that we should prioritize microservices refactoring before Q4.
- Jordan Lee presented data showing improvements in SMS Gateway after implementing microservices refactoring.
- Quinn Thompson recommended a proof-of-concept for microservices refactoring using User Service.
- According to Jordan Lee, we need to address data inconsistency before proceeding with microservices refactoring.
- Morgan Chen noted that Auth Service is currently experiencing security vulnerabilities.
- Jordan Lee suggested involving Data Team in the microservices refactoring initiative.

## Timeline

- Phase 1 (Week 1-2): Planning and requirements
- Phase 2 (Week 3-6): Implementation
- Phase 3 (Week 7-8): Testing and rollout

## Risks and Mitigations

- technical debt may impact timeline
- Resource constraints in Mobile Team
- Dependencies on Recommendation Engine
